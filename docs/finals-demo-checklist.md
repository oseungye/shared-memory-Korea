## C. 시연 중 문제가 생기면

| 증상 | 원인·대응 |
|---|---|
| “서버 응답이 늦어 요청을 멈췄습니다” | 15초 안에 Supabase 응답이 없음(망 문제). 쓰던 문장은 남아 있으니 잠시 뒤 다시 등록. 등록 시간 초과는 이미 저장됐을 수 있으니 목록을 먼저 확인 |
| “같은 제안이 방금 등록되었습니다” | 같은 내용을 5분 안에 다시 보냄 — 이미 저장된 상태. 목록에서 확인 |
| “지금 등록이 몰려 잠시 멈췄습니다” | 전체 등록이 1분에 120건 이상. 1분 뒤 다시 |
| 참여자 수가 안 보임 | 집계 함수 응답 실패 시 숨김(오류 아님) |
| AI 탭이 “아직 기록 전” | `ai-narratives-data.js`를 불러오지 못했거나 기록 형식 검사에서 모두 빠짐 — 새로고침 후에도 같으면 배포본 확인 |

## D. 심사위원 질문 대비 — 사실 확인용

- **AI가 정답을 판정하나요?** 아니요. 서술 비교는 자체 구현 NLP(TF-IDF·코사인·Jaccard·개념 사전)이고, AI 답변은 미리 기록한 것을 ‘네 번째 서술자’로 비교 대상에 놓을 뿐 실시간 호출·판정이 없습니다.
- **수치가 하드코딩인가요?** 아니요. 비교 분석은 서술 원문에서, 공동 기억 지도는 Supabase의 실제 제안에서 매번 계산합니다(“↻ 최신 참여 불러오기”로 시연 가능).
- **학생 정보는?** 이름·연락처·학교 미수집. 연령대(10년 단위)·학습 경험(4지선다)만, 5명 미만 연령대는 서버에서 가림. 닉네임·문장의 연락처·링크는 등록 차단.
- **악용·도배는?** DB 권한 최소화(조회·등록만), CHECK 제약, 서버 단 숨김(`is_hidden`), 동일 제안 재등록·1분 120건 초과 차단. 공감은 브라우저 키 기준 중복 방지만 있습니다(한계).
- **테스트는?** 단위 테스트 165개 + 실제 Chromium E2E 8개 스위트(278개 확인 항목), GitHub Actions에서 PR마다 실행. E2E는 가짜 DB를 쓰므로 RLS·트리거는 운영 DB 리허설(적용 → anon 권한 확인 → 롤백)로 확인했습니다.
