# Shared Memory — 동북아 역사 공동 기억 프로젝트

> 누가 옳은가를 AI가 판정하는 것이 아니라, 서로 다른 역사 서술이 어떤 언어와 관점을 사용하고 있는지 분석하고,
> 사용자가 실제 자료와 다른 참여자의 표현을 살펴본 뒤 자신만의 공동 표현을 제안하도록 돕는다.

한국·일본·중국의 역사 서술을 나란히 놓고 텍스트 분석(NLP)으로 비교한 뒤, 참여자가 직접 '공동 표현'을 제안하고,
모인 제안을 다시 분석해 **공동 기억이 형성되는 과정**을 데이터로 보여주는 디지털 인문학 웹 플랫폼입니다.
서버 없이 GitHub Pages에서 동작하며, 참여 데이터는 Supabase에 저장됩니다.

---

## 1. 프로젝트 목적과 문제의식

- 같은 사건도 한국에서는 '왜란', 일본에서는 '出兵', 중국에서는 '抗倭援朝'로 불립니다. 단어 선택은 곧 시선의 선택입니다.
- 역사 교육은 흔히 한 국가의 서술만 전달합니다. 이 프로젝트는 세 서술을 **같은 화면에서, 같은 방법으로** 분석해 차이와 공통점을 드러냅니다.
- 차이를 확인하는 데서 멈추지 않고, 참여자가 서로 다른 관점을 함께 담는 표현을 직접 써 보고, 그 표현들이 어떻게 모이는지 봅니다.
- 이 과정에서 사실(침략·강제 동원·피해 등)을 지우거나 약화시키는 "중립화"를 정답으로 제시하지 않습니다.

## 2. 프로젝트 흐름

```
한국·일본·중국 역사 서술 비교
  → NLP 분석 (핵심 키워드 · 공통/특징적 표현 · 유사도 · 서술 강조점)
  → 관련 사료 확인 (누가, 언제, 어떤 위치에서 쓴 기록인가)
  → 참여자 공동 표현 작성 (Guided Contribution, 실시간 표현 분석)
  → 공동 표현 NLP 분석 (어휘·개념 · 유사도 · 표현 프레이밍)
  → Shared Memory 형성 (표현군 · 공동 기억 지도 · 탐구 전/후 변화 · 공감)
```

### 3-1. 첫 방문 온보딩과 참여자 통계 (2026-10)

디자인(한지 배경·먹색·글꼴·히어로·지도 SVG·카드·버튼)은 그대로 두고, 처음 온 사람이 **무엇을 하는 곳인지 · 무엇을 하면 되는지 · 얼마나 걸리는지**를 바로 알 수 있도록 문구와 안내만 추가했습니다.

| 항목 | 내용 |
|---|---|
| 첫 화면 | 질문형 제목(“같은 역사를, 우리는 정말 같은 방식으로 기억하고 있을까요?”), **5분 탐구 시작하기** 버튼, `약 5분 · 익명 참여 · 로그인 필요 없음`, 참여 4단계(사건 선택 → 세 나라의 서술 비교 → 나의 공동 표현 작성 → 다른 사람들의 공동 기억 확인), 실제 참여자 수 |
| 참여자 수 | Supabase 집계 함수 `participation_summary()` 결과만 표시(하드코딩 없음). 집계 함수가 없거나 0명이면 문구를 숨깁니다 |
| 연령대 (익명) | 시작 버튼을 누르면 `10대 · 20대 · 30대 · 40대 · 50대 · 60대 이상 · 응답하지 않음` 중 하나를 버튼으로 고릅니다. 공동 표현 작성 폼에서도 바꿀 수 있습니다. → `age_group` |
| 학습 경험 | 사건을 연 뒤 “탐구 전 한 문장” 카드에서 “이 사건을 이전에 배워보거나 자세히 접한 적이 있나요?”(있다·없다·잘 모르겠다·응답하지 않음) → `prior_learning` |
| 탐구 진행 표시 | `사건 선택 → 처음 생각 → 서술 탐구 → 공동 표현 → 결과 확인`. 권장 흐름을 보여줄 뿐 탭 이동을 막지 않습니다. 각 단계를 누르면 해당 위치로 이동하고, “다음” 안내가 한 줄로 나옵니다 |
| 닉네임 | 선택 항목. 비워 두면 ‘익명’으로 저장합니다 |
| 세대별 필터 | 공동 기억 지도에 `전체 · 10대 … 60대 이상` 필터. 고른 연령대의 제안만 **기존 분석 함수(`analyzeExpressions`, `aggregateBeforeAfter`)에 그대로 넣어** 제안 수·주요 어휘·개념·프레임·표현군·대표 표현·서술 유사도·탐구 전/후 변화를 다시 계산합니다 |
| 세대별 표현 차이 | ‘전체’ 보기에 연령대별 참여자 수·많이 쓰인 개념·표현 프레임 비율·서술과의 평균 유사도를 나란히 보여주는 작은 표. 차이가 작으면 “차이가 크지 않았습니다”라고 그대로 표시합니다 |

**완료 참여자 기준** (`completed_flow = true`): 사건 선택 + 탐구 시작 기록(사건 상세 열기 또는 탐구 전 문장) + **국가별 서술 확인**(서술 카드가 화면의 상당 부분에 5초 이상 보임) + 공동 표현 제출. 단순 방문자는 참여자로 세지 않습니다. NLP·사료 탭 열람(`viewed_nlp`, `viewed_sources`)은 추가 분석용으로만 기록하며 완료 조건이 아닙니다. 클릭 로그는 남기지 않고 이 네 가지 milestone만 제출 시점에 함께 저장합니다.

**표본이 적은 집단**: 연령대별 참여자가 `MIN_GROUP_SIZE`(기본 5명, `generation-analysis.js`) 미만이면 세부 분석을 표시하지 않고 “표본이 적어 세부 분석을 표시하지 않습니다.”라고 보여줍니다. 이 제안들도 ‘전체’ 분석과 전체 참여자 수에는 포함됩니다. 표본 크기는 서버 집계(중복 제거된 참여자 수)와 제안 수 중 작은 값을 씁니다.

**개인정보**: 이름·연락처·생년월일·정확한 나이·학교명은 수집하지 않습니다. 연령대는 10년 단위 구간만, 학습 경험은 4개 선택지만 저장합니다. 화면 안내: “참여 내용은 익명으로 프로젝트 개선과 통계 분석에 활용됩니다. 이름·연락처·생년월일 등 개인정보는 수집하지 않습니다.”

**데이터 해석의 한계**
- **연령대별 표현 차이는 참여한 표본에서 관찰된 경향일 뿐, 해당 연령대 전체의 역사 인식을 대표하지 않습니다.**
- 참여자는 무작위 표본이 아닙니다(자발적 참여, 수업·지인 경로 등에 따라 치우칠 수 있음).
- “차이가 크지 않음”은 프레임 비율 차이 15%p 미만·서술 유사도 차이 0.05 미만일 때의 기술적 표현이며 통계적 유의성 검정이 아닙니다(`DIFF_THRESHOLDS`).
- 연령대·학습 경험은 자기 응답이며 검증하지 않습니다. 브라우저별 무작위 키 기준이라 다른 기기·브라우저에서 참여하면 다른 사람으로 세어질 수 있습니다.
- 이 SQL 이전에 저장된 제안은 참여자 키가 없어 제안 1건을 1명으로 추정해 셉니다.

## 5. NLP 방법론

모든 결과는 입력 텍스트에서 매번 계산됩니다. 분석 결과·비율·군집 이름을 코드에 미리 적어 두지 않습니다.

### 5-1. 국가별 서술 분석 (`nlp-analyzer.js`)

- **토큰화**: 어절 분리 → 규칙 기반 조사·어미 제거(예: 일본군을→일본군, 희생되었다→희생) → 불용어 제거. 각 토큰은 원문 위치(offset)를 기억합니다.
- **TF-IDF**: `TF × IDF`, `IDF = ln((1+N)/(1+df)) + 1`. 말뭉치는 사이트의 전체 서술(6개 사건 × 3개국).
- **공통 표현**: 세 서술에 모두 나온 단어·2어절 표현. 두 국가만 공유하는 표현도 따로 표시.
- **특징적 표현 (distinctive expression)**: 평활화된 상대 빈도 비율, 정렬은 로그 오즈비 z-점수(Monroe et al. 2008 방식 간소화).
- **코사인 유사도**: TF-IDF 벡터 간 코사인. 공유 단어별 기여도의 합 = 코사인 값 (설명 가능성).
- **Jaccard 유사도**: 공통 어휘 수 ÷ 전체 어휘 수.
- **원문 근거**: 선택한 단어·개념이 원문 어디에 쓰였는지 강조.

### 5-2. 개념 사전 (`concept-lexicon.js`)

사람이 만든 다국어 개념 사전입니다. 예) `침략 · 침공 · 侵略 · invasion → invasion`.
26개 개념을 **갈등·책임 / 사실·기술 / 화해·협력** 세 가지 표현 프레임으로 나눕니다.
기계학습 모델이 아니며, 목록에 없는 동의어·문맥은 인식하지 못합니다.

### 5-3. 서술 강조점 비교 (`emphasisProfile`)

개념 사전의 한국어 표현이 각 국가 서술에 나온 횟수 ÷ 서술의 어휘 토큰 수(밀도)를 구하고,
세 서술 중 최댓값을 3으로 두어 ●(0~3단계)로 표시합니다. **편향 탐지가 아닙니다.** 덜 언급했다고 왜곡이라고 판단할 수 없으며, 부정문도 언급으로 셉니다.

### 5-4. 키워드 비교 차트 (`keywordGroupCounts`)

`events-data.js`의 `keywordGroups`에는 사람이 정한 "표현 묶음"(예: `'침략': ['침략', '침공']`)만 있고,
숫자는 각 서술(제목+본문)에서 실제 등장 횟수를 세어 만듭니다. 예전의 수동 입력 숫자(`keywordFreq`)는 삭제했습니다.

### 5-5. 참여자 공동 표현 분석 (`shared-memory-analyzer.js`)

1. **언어 판별**: 한글·가나·라틴 문자 비율 (가나 없이 한자만 있으면 중국어와 구분할 수 없어 `unknown`).
2. **언어별 토큰화**: 한국어는 5-1과 같은 규칙, 일본어는 한자·가타카나 연속 구간, 영어는 불용어 제거 + 간단한 어미 정리.
3. **특징 벡터**: `단어` + `문자 2-gram`(가중치 0.5) + `개념`(가중치 1.5)을 TF-IDF로 가중. IDF는 해당 사건의 공동 표현 + 국가별 서술에서 계산.
   - 문자 2-gram 덕분에 "국제전쟁"과 "국제적인 전쟁"이 겹치고,
   - 개념 사전 덕분에 "일본의 침략"과 "日本の侵略", "Japanese invasion"이 같은 개념을 공유합니다.
4. **유사도**: 코사인 (0~1).
5. **표현군(군집화)**: 평균 연결(average-linkage) 병합 군집화. 평균 유사도가 가장 높은 두 묶음을 차례로 합치고 0.24 미만이면 멈춥니다. 무작위성이 없어 같은 데이터 → 같은 결과. 2건 이상인 묶음만 표현군으로 표시. 400건을 넘으면 앞 400건으로 묶은 뒤 나머지를 가장 가까운 묶음에 배정.
6. **표현군 설명**: 이름 = 절반 이상 제안에 나타난 개념(없으면 "군집 안 등장 제안 수 × IDF" 상위 어휘) → `‘국제·동아시아 · 전쟁’ 중심 표현군`처럼 자동 생성. 대표 제안 = 다른 제안들과 평균 유사도가 가장 높은 제안(medoid).
7. **지도 연결선**: 표현군 중심 벡터 간 코사인 ≥ 0.12.
8. **국가별 서술 ↔ 참여자 표현**: 참여자 주요 어휘가 세 서술 공통/일부 서술/서술에 없던 새 어휘 중 무엇인지, 반복 개념이 어느 서술에 있었는지, 참여자 제안과 각 서술의 평균 유사도.
9. **표현 프레이밍**: 개념 사전 기준 프레임별 어휘 수 (예전 "긍정/중립/부정 감정 분석"을 대체).
10. **탐구 전/후 비교**: 새롭게 등장·유지·사라진 어휘와 개념, 두 문장의 유사도, 국가별 서술과의 유사도 변화.
11. **작성 중 실시간 분석**: 선택한 요소 포함 여부, 사건 주요 어휘 포함 여부, 길이, 국가별 서술·기존 제안과의 유사도, 프레임 어휘, 탐구 전 문장과의 비교.

### 5-6. 의미 유사도(문장 임베딩)에 대해

브라우저용 다국어 문장 임베딩(예: transformers.js + 다국어 MiniLM)을 검토했지만 **사용하지 않았습니다.**

- 모델 파일이 수십~수백 MB라 GitHub Pages 첫 화면 로딩이 크게 느려지고, 모바일 데이터 부담이 큽니다.
- 외부 임베딩 API는 키를 브라우저 코드에 노출해야 합니다.

대신 **TF-IDF + 문자 n-gram + 다국어 개념 사전 + 코사인**으로 "표현은 다르지만 뜻이 가까운" 문장의 일부를 잡아냅니다.
따라서 화면과 문서에서 이 분석을 "AI", "임베딩", "의미 분석"이라고 부르지 않고 "텍스트 유사도"라고 부릅니다.
`analyzeExpressions`는 특징 벡터를 만드는 부분이 분리되어 있어, 나중에 서버(Edge Function)에서 임베딩을 계산하는 방식으로 확장할 수 있습니다.

## 6. 설명 가능성

- 모든 키워드에 등장 횟수·IDF·점수를 함께 표시합니다.
- 코사인 유사도는 기여 단어와 기여도(합 = 코사인 값)를 보여줍니다.
- 단어·개념 칩을 누르면 원문 위치가 강조되고, 연결된 사료가 나옵니다.
- 표현군마다 대표 키워드의 등장 건수, 표현군 안 평균 유사도, 실제 제안 목록을 보여줍니다.
- 각 분석 영역에 "분석 방법과 한계"를 펼쳐 볼 수 있습니다.
- 사람이 쓴 해석(편집자 해설, 표현 특징)은 자동 분석 결과와 구분해 표시합니다.

## 7. 분석의 한계

- 형태소 분석기가 아닌 규칙 기반 처리라 일부 활용형이 남거나 잘릴 수 있습니다.
- 개념 사전에 없는 동의어·비유·반어, 부정문("굴종이 아닌")은 구분하지 못합니다.
- 국가별 서술은 편집자가 요약한 짧은 텍스트이며, 각국 교과서·학계 전체를 대표하지 않습니다.
- 제안 수가 적으면 표현군이 불안정합니다. 가장 큰 표현군은 "많은 참여자가 비슷하게 쓴 방식"일 뿐 정답이 아닙니다.
- 공감 수는 참여자의 반응이며 역사적 정답의 순위가 아닙니다.
- 사료 메타데이터는 편집자 검토 전(`reviewed: false`) 상태입니다.

`age_group`·`prior_learning`은 다른 제안 내용과 마찬가지로 공개 조회되는 값입니다(브라우저에서 연령대별 분석을 하기 위해). 화면에서는 소수 표본을 숨기지만, 원자료 API에서는 행 단위로 보입니다. 더 엄격하게 하려면 연령대 집계를 서버 함수로 옮기세요.

**하위 호환**: SQL을 실행하기 전에도 사이트는 동작합니다. 저장은 ① 참여자 통계 컬럼 포함 → ② 작성 가이드 확장 컬럼까지 → ③ 기본 컬럼만 순서로 다시 시도합니다. 기존 행은 `age_group`이 없어 ‘전체’ 분석에만 포함되고, 참여자 수 문구는 집계 함수가 생길 때까지 숨겨집니다.

 확장 컬럼이 없으면 `shared-store.js`가 기존 컬럼만으로 다시 저장하고, 공감 기능은 숨겨집니다. 기존 행은 새 컬럼이 비어 있는 상태로 그대로 분석에 포함됩니다.

### RLS와 보안

- 브라우저에는 **publishable(anon) 키만** 있습니다. `service_role` 키·비밀 키를 절대 코드에 넣지 마세요.
- `shared_expressions`: 조회·등록만 허용, 수정·삭제 정책 없음 (현재 설정 유지).
- `expression_empathy`: 등록만 허용, 조회 정책 없음. 집계는 함수로만.
- 공감 중복 방지는 브라우저별 무작위 키 기준입니다. 저장소를 지우거나 다른 브라우저를 쓰면 다시 공감할 수 있습니다. 더 강하게 막으려면 Supabase 익명 로그인(Anonymous Sign-in) + `auth.uid()` 기준 UNIQUE를 권장합니다.
- 누구나 제안을 등록할 수 있으므로, 부적절한 게시물 대응(대시보드에서 삭제, 필요 시 `is_hidden` 컬럼 추가)과 요청 빈도 제한을 운영 중 검토하세요.
- 사용자 입력은 화면에 표시할 때 모두 `escapeHtml`로 처리하고, 지도 텍스트는 `textContent`로 넣습니다.
